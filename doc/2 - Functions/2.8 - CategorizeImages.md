# 2.8 Function: CategorizeImages (v0.1)

- Internal name: `CategorizeImages`
- Script: `System/Code/Images/CategorizeImages.ps1`
- Group: Bilder (`Images`)
- Called by its own button: **Bilder kategorisieren (Claude)** (GUI label, proposal), see `2 - FunctionOverview.md`
- Tooltip (GUI): „Lässt Claude lose Bilder grob einordnen (z. B. Rezepte), benennt erkannte Bilder passend um und verschiebt sie in den Ordner ihrer Kategorie“
- Uses endpoint `3.1 - ClaudeEndpoint.md` (Claude subscription, never pay per use).
- Extends the base specification v0.20 (`1 - Base.md`). The base stays unchanged. Where this function would need a change to the base, it is listed in section 9.
- Language: this document and the code are in English. Only GUI-visible values are in German.

## 1. Purpose
- Input: arbitrary single images that do **not** belong to an event (screenshots, photos of cookbook pages, saved pictures, …). Event photos are handled by 2.3, 2.6 and 2.7.
- Output: a coarse categorization. Each image gets exactly one category, either one of the defined categories or **Sonstiges** (`Other`) if none fits.
- Images of a defined category get a fitting new name and are moved into the folder of their category.
- The list of categories can be extended at any time without changing code (section 3). It always ends with `Other`.
- First category: **Rezepte** (`Recipe`).

## 2. Scope and target folders
- `InputAndResult` (proposal). Reads loose images in `Input`, moves only from `Input` to `Result`. Never moves anything inside `Result`.
- Next to `Result/Ereignisse` there is one folder per category plus one for the rest (Razen, 2026-10-30):
```
Result/
├─ Ereignisse/     event folders (2.3, 2.6, 2.7, 2.5)
├─ Rezepte/        category Recipe
├─ …               one folder per further category
└─ Sonstiges/      category Other
```
- A missing category folder is created by the plan (`FOLDER_CREATED`, green line in the preview).

## 3. Category list (`System/Config/categories.json`)
- One entry per category. A new category = a new entry, nothing else (proposal).
- Keys in English, values visible in the GUI in German:

```json
{
  "categories": [
    {
      "name": "Recipe",
      "label": "Rezepte",
      "folder": "Rezepte",
      "description": "A recipe: a list of ingredients and/or cooking or baking instructions, e.g. a cookbook page, a handwritten recipe card, a screenshot of a recipe website or a recipe post.",
      "naming": "Name of the dish in German, as it appears in the recipe, e.g. 'Kartoffelsuppe mit Speck'."
    }
  ],
  "other": { "name": "Other", "label": "Sonstiges", "folder": "Sonstiges" }
}
```

- `name`: internal name (English, used in database and log).
- `label`: name in the GUI. `folder`: folder name below `Result`.
- `description`: what belongs to the category, in English, goes into the prompt.
- `naming`: how Claude should build the new file name for this category, in English.
- `other` is fixed and cannot be removed. Images there keep their name.
- Order matters only for the display. The prompt contains all categories.

## 4. Which files
- Image files (`imageExtensions` from `settings.json`, see 2.3) lying **directly in `Input`**, not in subfolders (proposal). So day folders and other prepared folders are never touched.
- No videos.
- Images that were already categorized with the **same category list** are not sent again (database column `Category`, see section 9). If the category list changes (e.g. a new category is added), they are asked again.
- If Claude is not available (see 3.1), the button is greyed out with the reason as tooltip.

## 5. Procedure
1. **Collect** the loose images in `Input` (section 4). At most `maxCallsPerRun` (3.1) per run. The status bar says how many remain for a next run.
2. **Smaller copy:** for each image a temporary copy with at most `maxImageEdge` pixels on the long side (default 1568) is written to `System/Temp/Claude/`, so the call stays small. The original is not changed. The copy is removed after the call (temporary file of the tool, not a user file).
3. **Ask Claude:** one call per image. The prompt is built from `categories.json` (English):
   "Classify this image into exactly one of these categories: <name: description, …>, Other: anything that does not clearly fit. Answer only with JSON: {\"category\": one of <names>, \"confidence\": number from 0 to 1, \"title\": new file name following the naming rule of the category (<name: naming, …>), null for Other, \"reason\": short reason in German}."
4. **Check the answer:**
   - Unknown category or invalid JSON → `Other`, logged as `InvalidResponse`.
   - `confidence` below `minCategoryConfidence` (default 0.7) → proposed, but unchecked.
   - `title` is cleaned: characters not allowed in Windows file names (`\ / : * ? " < > |`) are removed, at most `maxTitleLength` characters (default 80). The original extension stays, e.g. `.jpg`.
5. **Plan:**
   - Category found: `Input/IMG_2231.jpg` → `Result/Rezepte/Kartoffelsuppe mit Speck.jpg`.
   - `Other`: `Input/IMG_2232.png` → `Result/Sonstiges/IMG_2232.png`, name unchanged.
   - Name conflict: base rule `_2`, e.g. the second page of the same recipe becomes `Kartoffelsuppe mit Speck_2.jpg`.
6. **Preview**, execute, log.
- Usage limit reached: as in 3.1 (wait, or „Rest überspringen“ and keep the results so far).

## 6. Preview
- Base preview (Git-style), grouped by category: „Rezepte (12)“, „Sonstiges (40)“. Both `Input` and `Result` are shown.
- Each row shows a small thumbnail, the old path (red), the new path (green) and Claude's confidence and reason, e.g. „Rezept – 92 % – Zutatenliste und Zubereitung“.
- The new name can be edited directly in the preview (as in 2.6). Only the part before the extension is editable.
- The category of a row can be changed with a dropdown (all categories plus „Sonstiges“). The target folder follows. When changed to a category, the name field is empty and must be filled in.
- Rows below `minCategoryConfidence` are unchecked and shown in grey italics.
- Unchecked rows stay in `Input` and are logged as `REJECTED`.

## 7. Privacy
- Only the smaller copy of each image is sent to Anthropic through the Claude subscription. No file names, no paths, no EXIF data (the copy is written without metadata).

## 8. Log and undo
- File name: `YYYY-MM-DD_HH-MM-SS - Images - CategorizeImages.log`.
- Moves and renames as `MOVED`, created category folders as `FOLDER_CREATED`, plus one `API_CALL` line per image with category, confidence and result.
- Undo as in the base: files go back to `Input` with their old name, category folders created by this action are removed if they become empty. Database paths follow.

## 9. Notes on the base (not entered there)
- **New config file** `System/Config/categories.json` next to `layout.json` and `settings.json`.
- **New columns** in table `Files`: `Category` (internal name, e.g. `Recipe`, `Other`) and `CategoryListHash` (hash of `categories.json` at the time of the call), so images are not sent twice for the same list.
- **Preview with thumbnail, editable name and category dropdown** per row. The base preview has no editable fields (as already noted in 2.6).
- **New folder** `System/Temp/Claude/` for the smaller copies (already used by 3.1 as working folder).
- **New settings** `maxImageEdge`, `minCategoryConfidence` and `maxTitleLength` in `settings.json` (section `categories`).

## 10. Open questions
1. **Result structure:** understood as `Result/Ereignisse`, `Result/Rezepte`, …, `Result/Sonstiges` side by side. Correct, or should the category folders be inside `Sonstiges`?
2. **Directly to Result:** this function moves straight from `Input` to `Result` (scope `InputAndResult`). Alternative: first into `Input/Rezepte` etc., and later with „Nach Result verschieben“ (2.5).
3. **Sonstiges into Result too:** unrecognized images go to `Result/Sonstiges` (checked by default). Alternative: they stay in `Input`. Note: when a new category is added later, images already in `Result/Sonstiges` are not looked at again, because nothing moves inside `Result`. Should there be an option „Sonstiges erneut prüfen“ that also reads `Result/Sonstiges`?
4. **Only loose images directly in Input:** subfolders of `Input` are ignored. OK?
5. **Recipe name:** only the dish name (`Kartoffelsuppe mit Speck.jpg`). Or with a prefix, e.g. source or type (`Kuchen - Apfelkuchen.jpg`)? Subfolders inside `Rezepte` (e.g. Backen, Kochen) not planned for now.
6. **Next categories:** which ones come next? Ideas: Screenshots, Dokumente/Belege, Memes, Notizen/Whiteboard.
