# 2.8 Function: CategorizeImages (v0.6)

- Internal name: `CategorizeImages`
- Script: `System/Code/Images/CategorizeImages.ps1`
- Group: Bilder (`Images`)
- Called by its own button: **Bilder kategorisieren (Claude)** (GUI label, proposal), see `2 - FunctionOverview.md`
- Tooltip (GUI): „Lässt Claude lose Bilder grob einordnen (z. B. Rezepte), benennt erkannte Bilder mit einem Schlagwort um und verschiebt sie in den Ordner ihrer Kategorie“
- Uses endpoint `3.1 - ClaudeEndpoint.md` (Claude subscription, never pay per use, confirmed).
- One specification per category: `2.8.<n> - <Category>.md` (Razen, 2026-10-30). Categories so far: `2.8.1 - Recipe.md`, `2.8.2 - Meme.md`, `2.8.3 - Screenshot.md`. Further categories follow.
- Extends the base specification v0.20 (`1 - Base.md`). The base stays unchanged. Where this function would need a change to the base, it is listed in section 10.
- Language: this document and the code are in English. Only GUI-visible values are in German.

## 1. Purpose
- Input: arbitrary single images that do **not** belong to an event (screenshots, photos of cookbook pages, saved pictures, …). Event photos are handled by 2.3, 2.6 and 2.7.
- Output: a coarse categorization. Each image gets exactly one category: one of the defined categories, or **Default** if none fits (Razen, 2026-10-30).
- Images of a defined category get a new name built from a keyword (Schlagwort) and are moved into the folder of their category.
- The list of categories can be extended at any time: a new category = a new category specification plus its definition file (section 3), no code change.

## 2. Scope and target folders
- `InputAndResult` (proposal). Reads loose images in `Input`, moves only from `Input` to `Result` or to a sort-out folder in the main folder (see below). Never moves anything inside `Result`.
- **Categories to keep** go to `Result`. Next to `Result/Ereignisse` there is one folder per category plus one for Default (Razen, 2026-10-30):
```
Result/
├─ Ereignisse/     event folders (2.3, 2.6, 2.7, 2.5)
├─ Rezepte/        category Recipe (2.8.1)
├─ Screenshots/    category Screenshot (2.8.3)
├─ …               one folder per further category (2.8.<n>)
└─ Sonstiges/      Default: images no category fits
```
- **Categories to sort out** (meant to be deleted later, e.g. Memes) go to their own subfolder of the main folder `ToDelete`, next to `ToDelete/Doublets` (Razen, 2026-10-30):
```
SortingTool/
├─ Input/
├─ Result/
├─ ToDelete/
│  ├─ Doublets/    duplicates (2.2)
│  └─ Memes/       category Meme (2.8.2)
└─ System/
```
  - The tool itself never deletes anything there (base rule). You empty the folder yourself.
  - `ToDelete` is not shown in the explorer (base v0.24), and `RemoveStaleEntries` (2.4) also covers it.
- A missing category folder is created by the plan (`FOLDER_CREATED`, green line in the preview).

## 3. Category definitions
- Each category has its own specification `2.8.<n> - <Category>.md`. It describes what belongs to the category, what does not, how the keyword is built and which folder it goes to.
- From each specification there is one definition file the tool reads: `System/Config/Categories/<Category>.json`. Keys in English, GUI values in German. Common format:

```json
{
  "name": "Recipe",
  "label": "Rezepte",
  "folder": "Rezepte",
  "target": "Result",
  "namePatterns": ["rezept", "recipe"],
  "definition": "English text: what belongs to this category and what does not.",
  "keywordRule": "English text: how to build the keyword for the file name."
}
```

- `name`: internal name (English, used in database, log and Claude's answer).
- `label`: name in the GUI. `folder`: folder name.
- `target`: where `folder` lies. `Result` (default): `Result/<folder>`, category to keep. `ToDelete`: `ToDelete/<folder>`, sorted out to be deleted later.
- `minConfidence` (optional): own confidence limit for this category, overrides `minCategoryConfidence`.
- `keywordPrefix` (optional): `CaptureDate` puts `YYYY-MM-DD - ` (capture date from the database) in front of the keyword (e.g. Screenshots).
- `rename`: `true` (default) or `false`. With `false` the file keeps its name and Claude is asked for no keyword (e.g. Memes).
- `namePatterns` (optional): words for the pre-assessment by file name (section 5a). Not sent to Claude.
- `definition` and `keywordRule` are sent to Claude, word for word as in the category specification.
- **Default** is not a category file. It is fixed in this function: internal name `Default`, GUI label „Sonstiges“, folder `Result/Sonstiges`. Images there keep their name.
- A category file can be switched off with `"enabled": false` (optional, default `true`).

## 4. Which files
- Image files (`imageExtensions` from `settings.json`, see 2.3) lying **directly in `Input`**, not in subfolders (proposal). So day folders and other prepared folders are never touched.
- No videos.
- Images that were already categorized with the **same set of category definitions** are not sent again (database columns, see section 10). If a category is added or changed, they are asked again.
- If Claude is not available (see 3.1), the button still works, but only with the pre-assessment by file name (section 5a). All rows are then unchecked, and the preview says (GUI): „Claude ist nicht verfügbar. Nur Voreinschätzung nach Dateiname.“

## 5. Procedure
1. **Collect** the loose images in `Input` (section 4). At most `maxCallsPerRun` (3.1) per run. The status bar says how many remain for a next run.
1a. **Pre-assessment by file name** (Razen, 2026-10-30), see section 5a. Runs locally for all collected images, free and before any Claude call.
2. **Smaller copy:** for each image a temporary copy with at most `maxImageEdge` pixels on the long side (default 1568), without metadata, is written to `System/Temp/Claude/`, so the call stays small. The original is not changed. The copy is removed after the call (temporary file of the tool, not a user file).
3. **Ask Claude:** one call per image, with the image and the definitions of **all** enabled categories together (Razen, 2026-10-30). Prompt (English), built from the definition files:
   ```
   Decide which one of the following categories this image belongs to.
   Category "<name>": <definition> Keyword: <keywordRule>
   … (one block per category)
   If no category clearly fits, set category to null.
   Answer only with JSON: {"category": one of the names above or null,
   "keyword": keyword following the rule of the category, null if category is null,
   "confidence": number from 0 to 1, "reason": short reason in German}
   ```
4. **Check the answer:**
   - `category` is `null` → **Default**.
   - Unknown category or invalid JSON → Default, logged as `InvalidResponse`.
   - `confidence` below `minCategoryConfidence` (default 0.7, or `minConfidence` of the category) → proposed, but unchecked.
   - `keyword` is cleaned: characters not allowed in Windows file names (`\ / : * ? " < > |`) are removed, at most `maxKeywordLength` characters (default 80). Empty keyword for a category → row unchecked, name field empty.
5. **Plan:**
   - Category found: `Input/IMG_2231.jpg` → `Result/<folder>/<keyword>.<original extension>`, e.g. `Result/Rezepte/Kartoffelsuppe mit Speck.jpg`, or with `keywordPrefix` `Result/Screenshots/2023-05-14 - Bahnticket Berlin München.png`.
   - Sort-out category (`target` `ToDelete`, `rename` `false`): `Input/IMG_2233.jpg` → `ToDelete/Memes/IMG_2233.jpg`, name unchanged.
   - Default: `Input/IMG_2232.png` → `Result/Sonstiges/IMG_2232.png`, name unchanged.
   - Name conflict: base rule `_2`.
6. **Preview**, execute, log.
- Usage limit reached: as in 3.1 (wait, or „Rest überspringen“ and keep the results so far).

## 5a. Pre-assessment by file name
- Many file names already hint at the content, e.g. `Chefkoch_Lasagne.jpg`, `Rezept Omas Apfelkuchen.png`, `meme_2023_42.jpg`, `9gag_abc.webp`. The tool uses this as a first guess, without Claude.
- **Overlapping categories:** a screenshot of a recipe matches Screenshot by name but is a Recipe by content. That is expected; Claude decides and the more specific category wins (rule in 2.8.3).
- **Rule:** the file name without extension is compared with the `namePatterns` of every enabled category.
  - Comparison ignores case, umlauts are compared as written and as `ae`/`oe`/`ue`/`ss` (`Kuchen`, `Brötchen` = `Broetchen`).
  - A pattern is a plain word or a part of a word (`rezept` matches `Rezepte_2021.jpg`). Patterns with `*` and `?` are Windows wildcards (`IMG-*-WA*` for WhatsApp images).
  - Separators `_`, `-`, `.` and spaces count as word boundaries.
- **Result per image:** the category with the most matching patterns, plus the words that matched, e.g. „Rezepte (Dateiname: ‚rezept‘, ‚chefkoch‘)“. No match: no pre-assessment. Tie between categories: no pre-assessment, both are shown as a hint.
- Generic camera names (`IMG_1234`, `DSC01234`, `PXL_…`, `IMG-…-WA…`) give no pre-assessment. The list of such names is `genericNamePatterns` in `settings.json`.
- **Use of the pre-assessment:**
  - It is only a hint. **Claude decides** when it is available. The pre-assessment is not sent to Claude (privacy, section 7).
  - Claude and pre-assessment agree → normal row, the hint is shown as a confirmation.
  - Claude and pre-assessment disagree → row unchecked and marked (GUI): „Dateiname deutet auf <Kategorie> hin, Claude sagt <Kategorie>“. You decide in the preview.
  - Claude not available, limit reached and „Rest überspringen“ chosen, or `maxCallsPerRun` reached → images with a pre-assessment are proposed with that category, but **unchecked**, keyword empty (for `rename` `true` you type it in), row marked „nur Voreinschätzung“.
  - Sort-out categories (e.g. Memes) are never checked based on the file name alone, since those files are deleted later.
- The pre-assessment is written to the log (`PREASSESSMENT` lines with category and matched words) and to the database column `NameHint`.

## 6. Preview
- Base preview (Git-style), grouped by category: „Rezepte (12)“, „Memes (25)“, „Sonstiges (40)“. `Input`, `Result` and `ToDelete` are shown.
- Groups of sort-out categories carry a note (GUI): „Zum späteren Löschen aussortiert“.
- Each row shows a small thumbnail, the old path (red), the new path (green) and Claude's confidence and reason, e.g. „Rezepte – 92 % – Zutatenliste und Zubereitung“, plus the pre-assessment by file name if there is one (section 5a).
- A filter above the list (GUI): „Alle“, „Nur Abweichungen“ (Claude and file name disagree), „Nur Voreinschätzung“.
- The keyword can be edited directly in the preview (as in 2.6). Only the part before the extension is editable.
- The category of a row can be changed with a dropdown (all categories plus „Sonstiges“). The target folder follows. When changed to a category, the name field is empty and must be filled in.
- Rows below `minCategoryConfidence` are unchecked and shown in grey italics.
- Unchecked rows stay in `Input` and are logged as `REJECTED`.

## 7. Privacy
- Only the smaller copy of each image (without metadata) and the category definitions are sent to Anthropic through the Claude subscription. No file names, no paths, no GPS.

## 8. Log and undo
- File name: `YYYY-MM-DD_HH-MM-SS - Images - CategorizeImages.log`.
- Moves and renames as `MOVED`, created category folders as `FOLDER_CREATED`, `PREASSESSMENT` lines (section 5a), plus one `API_CALL` line per image with category, keyword, confidence and result.
- Undo as in the base: files go back to `Input` with their old name, category folders created by this action are removed if they become empty. Database paths follow.

## 10. Notes on the base (not entered there)
- **Main folder `ToDelete`** (base v0.24) gets one subfolder per sort-out category (`target` `ToDelete`).
- **New config folder** `System/Config/Categories/` with one definition file per category.
- **New step type** `PREASSESSMENT` (information only, nothing to undo).
- **New columns** in table `Files`: `Category` (internal name, e.g. `Recipe`, `Default`), `Keyword`, `NameHint` (pre-assessment by file name) and `CategorySetHash` (hash over all enabled definition files at the time of the call), so images are not sent twice for the same set.
- **Preview with thumbnail, editable name and category dropdown** per row. The base preview has no editable fields (as already noted in 2.6).
- **Temporary copies** in `System/Temp/Claude/` (already the working folder of 3.1).
- **New settings** `maxImageEdge`, `minCategoryConfidence`, `maxKeywordLength` and `genericNamePatterns` in `settings.json` (section `categories`).

## 11. Open questions
1. **Result structure:** understood as `Result/Ereignisse`, `Result/Rezepte`, …, `Result/Sonstiges` side by side. Correct?
2. **Directly to Result:** this function moves straight from `Input` to `Result` (scope `InputAndResult`). Alternative: first into category folders in `Input`, later with „Nach Result verschieben“ (2.5).
3. **Default into Result too:** unrecognized images go to `Result/Sonstiges`, checked by default. Alternative: they stay in `Input`. Note: when a new category is added later, images in `Result/Sonstiges` are not looked at again. Should there be an option „Sonstiges erneut prüfen“ that also reads `Result/Sonstiges`?
4. **Only loose images directly in Input:** subfolders of `Input` are ignored. OK?
5. **File name to Claude:** the file name is not sent (privacy). It could be sent as an extra hint, which may help Claude (e.g. `Chefkoch_Lasagne.jpg`). Send it or not?
6. **Folder names as hint too:** only the file name is used. Should the name of the folder the image came from count as well (e.g. an image from a folder `Rezepte Oma` that was dropped flat into Input)? Since only loose images are processed, there is no folder for now.
