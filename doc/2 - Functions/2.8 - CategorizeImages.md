# 2.8 Function: CategorizeImages (v0.7)

- Internal name: `CategorizeImages`
- Script: `System/Code/Images/CategorizeImages.ps1`
- Group: Bilder (`Images`)
- Called by its own button: **Bilder kategorisieren (Claude)** (GUI label, proposal), see `2 - FunctionOverview.md`
- Tooltip (GUI): „Lässt Claude Bilder in Input grob einordnen (z. B. Rezepte, Screenshots), benennt erkannte Bilder mit einem Schlagwort um und sortiert sie in Input in Kategorieordner vor“
- Uses endpoint `3.1 - ClaudeEndpoint.md` (Claude subscription, never pay per use, confirmed).
- One specification per category: `2.8.<n> - <Category>.md` (Razen, 2026-10-30). Categories so far: `2.8.1 - Recipe.md`, `2.8.2 - Meme.md`, `2.8.3 - Screenshot.md`. Further categories follow.
- The pre-sorted category folders are moved over later by its own step `2.9 - MoveCategoryFolders.md` (Razen, 2026-10-30).
- Extends the base specification v0.20 (`1 - Base.md`). The base stays unchanged. Where this function would need a change to the base, it is listed in section 10.
- Language: this document and the code are in English. Only GUI-visible values are in German.

## 1. Purpose
- Input: arbitrary images that do **not** belong to an event (screenshots, photos of cookbook pages, saved pictures, …). Event photos are handled by 2.3, 2.6 and 2.7.
- Output: a coarse categorization. Each image gets exactly one category: one of the defined categories, or **Default** („Sonstiges“) if none fits (Razen, 2026-10-30).
- Images of a defined category get a new name built from a keyword (Schlagwort) and are **pre-sorted in `Input`** into a folder named like the category's target folder (Razen, 2026-10-30).
- The list of categories can be extended at any time: a new category = a new category specification plus its definition file (section 3), no code change.

## 2. Scope and folders
- `Input` only (confirmed). This function moves only inside `Input`. Moving the category folders to `Result` or `ToDelete` is done by `2.9 - MoveCategoryFolders.md`.
- **Pre-sorting in `Input`** (confirmed). The folders in `Input` have the same names as in the target:
```
Input/
├─ Rezepte/         category Recipe (2.8.1), with subfolders Kochen, Backen, …
├─ Screenshots/     category Screenshot (2.8.3), with one subfolder per year
├─ Memes/           category Meme (2.8.2)
├─ Sonstiges/       Default: images no category fits (confirmed, stays in Input)
└─ …                other images and folders, not yet categorized
```
- **Final targets** (confirmed), reached with 2.9:
```
Result/
├─ Ereignisse/      event folders (2.3, 2.6, 2.7, 2.5)
├─ Rezepte/         Recipe
├─ Screenshots/     Screenshot
├─ …                further categories to keep
└─ Sonstiges/       Default
ToDelete/
├─ Doublets/        duplicates (2.2)
└─ Memes/           Meme, to be deleted later by you
```
- A missing category folder in `Input` is created by the plan (`FOLDER_CREATED`, green line in the preview).

## 3. Category definitions
- Each category has its own specification `2.8.<n> - <Category>.md`. It describes what belongs to the category, what does not, how the keyword is built and which folder it goes to.
- From each specification there is one definition file the tool reads: `System/Config/Categories/<Category>.json`. Keys in English, GUI values in German. Common format:

```json
{
  "name": "Recipe",
  "label": "Rezepte",
  "folder": "Rezepte",
  "target": "Result",
  "namePatterns": ["rezept", "recipe"],
  "subfolders": [ { "folder": "Backen", "description": "English text for Claude" } ],
  "definition": "English text: what belongs to this category and what does not.",
  "keywordRule": "English text: how to build the keyword for the file name."
}
```

- `name`: internal name (English, used in database, log and Claude's answer).
- `label`: name in the GUI. `folder`: folder name, the same in `Input` and in the target.
- `target`: where 2.9 moves the folder. `Result` (default): `Result/<folder>`, category to keep. `ToDelete`: `ToDelete/<folder>`, sorted out to be deleted later.
- `minConfidence` (optional): own confidence limit for this category, overrides `minCategoryConfidence`.
- `keywordPrefix` (optional): `CaptureDate` puts `YYYY-MM-DD - ` (capture date from the database) in front of the keyword (e.g. Screenshots).
- `rename`: `true` (default) or `false`. With `false` the file keeps its name and Claude is asked for no keyword (e.g. Memes).
- `subfolders` (optional): list of subfolders inside the category folder, each with a description. Claude chooses one (e.g. Recipes: Kochen, Backen, Getränke). If none fits, the image goes directly into the category folder.
- `subfolderByYear` (optional, `true`/`false`): one subfolder per year of the capture date, e.g. `Screenshots/2023/`. Determined locally, not by Claude.
- `namePatterns` (optional): words for the pre-assessment by file name (section 5a). Not sent to Claude.
- `definition`, `keywordRule` and the subfolder descriptions are sent to Claude, word for word as in the category specification.
- **Default** is not a category file. It is fixed in this function: internal name `Default`, GUI label „Sonstiges“, folder `Input/Sonstiges`, later `Result/Sonstiges`. Images there keep their name.
- A category file can be switched off with `"enabled": false` (optional, default `true`).

## 4. Which files
- Image files (`imageExtensions` from `settings.json`, see 2.3) anywhere in `Input`, **including subfolders** (Razen, 2026-10-30). No videos.
- **Not included:**
  - The category folders themselves (`Input/Rezepte`, `Input/Screenshots`, `Input/Memes`, …, i.e. every `folder` of a category definition), since their content is already sorted.
  - Day folders of the event workflow (`YYYY-MM-DD` and `YYYY-MM-DD - …`, see 2.3) (proposal), so event photos are not categorized.
- `Input/Sonstiges` is included again only for images that were categorized with a **different set of category definitions** (e.g. after a new category was added). There is no extra option for this (confirmed: you check again yourself after a new category).
- Images that were already categorized with the **same set of category definitions** are not sent again (database columns, see section 10).
- If Claude is not available (see 3.1), the button still works, but only with the pre-assessment by file name (section 5a). All rows are then unchecked, and the preview says (GUI): „Claude ist nicht verfügbar. Nur Voreinschätzung nach Dateiname.“

## 5. Procedure
1. **Collect** the images (section 4). At most `maxCallsPerRun` (3.1) per run. The status bar says how many remain for a next run.
2. **Pre-assessment by file name**, see section 5a. Runs locally for all collected images, free and before any Claude call.
3. **Smaller copy:** for each image a temporary copy with at most `maxImageEdge` pixels on the long side (default 1568), without metadata, is written to `System/Temp/Claude/`, so the call stays small. The original is not changed. The copy is removed after the call (temporary file of the tool, not a user file).
4. **Ask Claude:** one call per image, with the image, its **file name as a hint** (confirmed) and the definitions of **all** enabled categories together. Prompt (English), built from the definition files:
   ```
   Decide which one of the following categories this image belongs to.
   The original file name is "<file name>". Use it only as a hint; the image content decides.
   Category "<name>": <definition> Keyword: <keywordRule> Subfolders: <folder: description, …>
   … (one block per category)
   If no category clearly fits, set category to null.
   Answer only with JSON: {"category": one of the names above or null,
   "keyword": keyword following the rule of the category, null if category is null,
   "subfolder": one of the subfolders of the category or null,
   "confidence": number from 0 to 1, "reason": short reason in German}
   ```
5. **Check the answer:**
   - `category` is `null` → **Default**.
   - Unknown category or invalid JSON → Default, logged as `InvalidResponse`. Unknown subfolder → no subfolder.
   - `confidence` below `minCategoryConfidence` (default 0.7, or `minConfidence` of the category) → proposed, but unchecked.
   - `keyword` is cleaned: characters not allowed in Windows file names (`\ / : * ? " < > |`) are removed, at most `maxKeywordLength` characters (default 80). Empty keyword for a category with `rename` `true` → row unchecked, name field empty.
6. **Plan** (all inside `Input`):
   - Recipe: `Input/Downloads/IMG_2231.jpg` → `Input/Rezepte/Backen/Apfelkuchen.jpg`.
   - Screenshot: `Input/Screenshot_20230514-101112.png` → `Input/Screenshots/2023/2023-05-14 - Bahnticket Berlin München.png`.
   - Meme (`rename` `false`): `Input/IMG_2233.jpg` → `Input/Memes/IMG_2233.jpg`, name unchanged.
   - Default: `Input/IMG_2232.png` → `Input/Sonstiges/IMG_2232.png`, name unchanged. Already in `Input/Sonstiges` and still Default → no change.
   - Name conflict: base rule `_2`.
   - Empty folders left in `Input` are removed by the main program (base rule).
7. **Preview**, execute, log.
- Usage limit reached: as in 3.1 (wait, or „Rest überspringen“ and keep the results so far).

## 5a. Pre-assessment by file name
- Many file names already hint at the content, e.g. `Chefkoch_Lasagne.jpg`, `Rezept Omas Apfelkuchen.png`, `meme_2023_42.jpg`, `Screenshot_20230514-101112.png`. The tool uses this as a first guess, without Claude (Razen, 2026-10-30).
- **Overlapping categories:** a screenshot of a recipe matches Screenshot by name but is a Recipe by content. That is expected; Claude decides and the more specific category wins (rule in 2.8.3).
- **Rule:** the file name without extension is compared with the `namePatterns` of every enabled category.
  - Comparison ignores case, umlauts are compared as written and as `ae`/`oe`/`ue`/`ss` (`Brötchen` = `Broetchen`).
  - A pattern is a plain word or a part of a word (`rezept` matches `Rezepte_2021.jpg`). Patterns with `*` and `?` are Windows wildcards.
  - Separators `_`, `-`, `.` and spaces count as word boundaries.
- **Result per image:** the category with the most matching patterns, plus the words that matched, e.g. „Rezepte (Dateiname: ‚rezept‘, ‚chefkoch‘)“. No match: no pre-assessment. Tie between categories: no pre-assessment, both are shown as a hint.
- Generic camera names (`IMG_1234`, `DSC01234`, `PXL_…`, `IMG-…-WA…`) give no pre-assessment. The list of such names is `genericNamePatterns` in `settings.json`.
- **Use of the pre-assessment:**
  - It is only a hint. **Claude decides** when it is available. Claude gets the file name itself (step 4), not the result of the pre-assessment.
  - Claude and pre-assessment agree → normal row, the hint is shown as a confirmation.
  - Claude and pre-assessment disagree → row unchecked and marked (GUI): „Dateiname deutet auf <Kategorie> hin, Claude sagt <Kategorie>“. You decide in the preview.
  - Claude not available, limit reached and „Rest überspringen“ chosen, or `maxCallsPerRun` reached → images with a pre-assessment are proposed with that category, but **unchecked**, keyword empty (for `rename` `true` you type it in), row marked „nur Voreinschätzung“.
  - Sort-out categories (e.g. Memes) are never checked based on the file name alone, since those files are deleted later.
- The pre-assessment is written to the log (`PREASSESSMENT` lines with category and matched words) and to the database column `NameHint`.

## 6. Preview
- Base preview (Git-style), grouped by category: „Rezepte (12)“, „Screenshots (30)“, „Memes (25)“, „Sonstiges (40)“. Only `Input` is shown.
- The Memes group carries a note (GUI): „Wird später zum Löschen aussortiert“.
- Each row shows a small thumbnail, the old path (red), the new path (green) and Claude's confidence and reason, e.g. „Rezepte › Backen – 92 % – Zutatenliste und Zubereitung“, plus the pre-assessment by file name if there is one (section 5a).
- A filter above the list (GUI): „Alle“, „Nur Abweichungen“ (Claude and file name disagree), „Nur Voreinschätzung“.
- The keyword can be edited directly in the preview (as in 2.6). Only the part before the extension is editable.
- The category of a row can be changed with a dropdown (all categories plus „Sonstiges“), the subfolder with a second dropdown. The target folder follows. When changed to a category, the name field is empty and must be filled in.
- Rows below `minCategoryConfidence` are unchecked and shown in grey italics.
- Unchecked rows stay where they are and are logged as `REJECTED`.

## 7. Privacy
- Sent to Anthropic through the Claude subscription: the smaller copy of each image (without metadata), its file name (confirmed) and the category definitions. No folder paths, no GPS.
- Screenshots may be sent to Claude as well, even though they are often private (confirmed).

## 8. Log and undo
- File name: `YYYY-MM-DD_HH-MM-SS - Images - CategorizeImages.log`.
- Moves and renames as `MOVED`, created folders as `FOLDER_CREATED`, `PREASSESSMENT` lines (section 5a), plus one `API_CALL` line per image with category, subfolder, keyword, confidence and result.
- Undo as in the base: files go back to their old place in `Input` with their old name, removed empty folders are created again. Database paths follow.
