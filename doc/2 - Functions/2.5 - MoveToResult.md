# 2.5 Function: MoveToResult (v0.3)

- Internal name: `MoveToResult`
- Script: `System/Code/Database/MoveToResult.ps1`
- Called by fixed button: **Nach Result verschieben** (GUI label, proposal), bottom of the main window next to the other fixed buttons, not part of any group (confirmed), see `2 - FunctionOverview.md`
- Tooltip (GUI): „Verschiebt ausgewählte Dateien oder Ordner aus Input in einen Ordner in Result“
- Extends the base specification v0.20 (`1 - Base.md`). The base stays unchanged. Where this function would need a change to the base, it is listed in section 8.
- Language: this document and the code are in English. Only GUI-visible values are in German.

## 1. Purpose
- Moves files or folders that are finished in `Input` into a chosen folder in `Result` (confirmed).
- You choose by hand what goes where: checkboxes for the source, a tree dropdown for the target.

## 2. Scope
- `InputAndResult` (confirmed). Reads the folder structure of `Result`, moves only from `Input` to `Result`.
- Never moves anything out of `Result` and never moves anything inside `Result`.

## 3. Setting
- `settings.json`: `resultTargetDepth`, default `2` (confirmed).
- Meaning: how many folder levels of `Result` the target dropdown shows.
  - `1`: only the folders directly in `Result`, e.g. `Ereignisse`, `Porträts`.
  - `2`: additionally their subfolders, e.g. `Porträts › Anna`, `Porträts › Ben`.

## 4. Selection dialog
Opens when the button is clicked. Elements (GUI labels in German):

- **Source tree** „Was soll verschoben werden?“: the content of `Input` as a tree. Every file and every folder has a checkbox, all unchecked at the start.
  - Checking a folder moves the whole folder with its content.
  - Checking a folder also checks everything below it. Unchecking single files inside then moves only the rest (see section 5).
- **Target dropdown** „Ziel in Result“: a tree dropdown (combo box that opens a tree) with the folders of `Result` up to `resultTargetDepth` levels.
  - Folders with subfolders can be expanded and collapsed in the dropdown.
  - Every node can be chosen, also the upper level, e.g. `Porträts` itself, and also `Result` itself as the top entry.
  - A last entry „Neuer Ordner …“ asks for a name and creates the folder below the chosen node, within the allowed depth (confirmed). The new folder appears in the preview as a green line and is only created on „Ausführen“.
- Buttons: „Vorschau“ (opens the preview, only active when something is checked and a target is chosen) and „Abbrechen“.
- One target per run. To move things to different targets, run the function again.

## 5. Plan
- **Checked file:** moved directly into the target folder, e.g. `Input/IMG_0412.jpg` → `Result/Porträts/Anna/IMG_0412.jpg`.
- **Checked folder:** moved with its name and content into the target folder, e.g. `Input/2024-07-13/` → `Result/Ereignisse/2024-07-13/`.
- **Folder partly checked:** the folder is created in the target and only the checked files go into it. The rest stays in `Input`.
- **Folder with the same name already in the target:** contents are merged, i.e. files go into the existing folder (confirmed).
- **Name conflict for files** (confirmed): base rule, the arriving file gets `_2`, `_3` etc., e.g. `IMG_0412_2.jpg`. A different hash proves it is a different file, not a duplicate.
- If the file in the target has the **same hash**, it is a duplicate after all (e.g. `FindDuplicates` was skipped). It is then not moved, shown as a conflict in the preview and logged as `REJECTED` with the hint to run „Input initialisieren“ first.
- Empty folders left in `Input` are removed by the main program as in the base.

## 6. Preview and checks
- Base preview (Git-style). Because the function works in `Input` and `Result`, both folders are shown.
- Warning before the preview if a checked file has not been checked for duplicates yet (`DuplicateChecked` empty): GUI message „Einige Dateien wurden noch nicht auf Doubletten geprüft. Vorher „Input initialisieren“ ausführen?“ with „Trotzdem fortfahren“ and „Abbrechen“.

## 7. Log and undo
- File name: `YYYY-MM-DD_HH-MM-SS - Database - MoveToResult.log`.
- Step types as in the base: `MOVED`, `FOLDER_CREATED`, `EMPTY_FOLDER_REMOVED`, `REJECTED`.
- Undo as in the base: files go back to their old place in `Input`, folders created in `Result` by this action are removed if they become empty, removed empty folders in `Input` are created again.
- Database paths are updated with every move (base rule).

## 8. Notes on the base (not entered there)
- **New fixed button** „Nach Result verschieben“. Base section 5 lists only three fixed buttons.
- **Selection dialog before the preview:** base functions go straight to the preview. This function first asks what and where.
- **New control type:** tree dropdown (Windows Forms has none built in, so it is built from a combo box with a tree view).
- **New setting** `resultTargetDepth` in `settings.json`.
