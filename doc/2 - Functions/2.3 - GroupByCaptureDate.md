# 2.3 Function: GroupByCaptureDate (v0.7)

- Internal name: `GroupByCaptureDate`
- Script: `System/Code/Images/GroupByCaptureDate.ps1`
- Group: Bilder (`Images`)
- Called by button: **Nach Aufnahmedatum gruppieren** (GUI label, proposal), see `2 - FunctionOverview.md`
- Tooltip (GUI): „Legt für jeden Aufnahmetag einen Ordner an und verschiebt die Bilder dieses Tages hinein“
- Extends the base specification v0.20 (`1 - Base.md`). The base stays unchanged. Where this function would need a change to the base, it is listed in section 8.
- Language: this document and the code are in English. Only GUI-visible values are in German.

## 1. Purpose
- Groups the files lying directly in `Input` by the day they were taken: one folder per day, the files of that day go into it.
- "Day" means the capture date (`CaptureDate`), i.e. the date the photo was taken, not the date of a copy (confirmed). How it is determined: `2.1 - InitializeFolder.md` section 4.
- **Never renames files** (confirmed). Every file keeps exactly its name. The function only creates day folders and moves files into them.
- A day folder is only worth it if enough photos were taken on that day. Days with fewer files are unchecked by default, but can be checked by hand.

## 2. Scope
- `Input` only (confirmed). Reads and moves files only within `Input`. The day folders are created in `Input`, e.g. `Input/2024-07-13/`.

## 3. Input files
- Assumption: the files lie flat directly in `Input` (confirmed). Files in subfolders of `Input` are ignored and stay where they are.
- **Warning for other folders** (confirmed): if `Input` already contains folders whose name is not a day folder in the format `YYYY-MM-DD`, a warning appears before the preview and lists them:
  - GUI text: „Die folgenden Ordner in Input haben kein Datumsformat und werden ignoriert:“, then one folder per line.
  - Buttons: „Weiter“ (opens the preview, the listed folders stay untouched) and „Abbrechen“.
  - Existing day folders in the format `YYYY-MM-DD` are not listed. New files of that day are moved into them.
- All image and video files (confirmed). Other files are ignored and stay where they are.
- The file types are listed in `settings.json`, so they can be extended without changing code:
  - `imageExtensions`, default: `.jpg`, `.jpeg`, `.png`, `.gif`, `.bmp`, `.heic`, `.heif`, `.webp`, `.tif`, `.tiff`, RAW `.cr2`, `.cr3`, `.nef`, `.arw`, `.orf`, `.rw2`, `.dng`
  - `videoExtensions`, default: `.mp4`, `.mov`, `.m4v`, `.avi`, `.mkv`, `.3gp`, `.mts`, `.m2ts`, `.wmv`
- Requires that `Input` has been initialized, so the capture date is in the database. Files without a database entry get one on the fly (base rule).

## 4. Procedure
1. **Collect:** all matching files directly in `Input` with their `CaptureDate`.
2. **Group:** by calendar day of `CaptureDate`.
3. **Folder name:** the day in the date format used everywhere in the tool (also in log names): `YYYY-MM-DD`, e.g. `2024-07-13`.
4. **Plan:** for each day: create folder `Input/2024-07-13/`, move the files of that day into it.
5. **Pre-check:** every day folder with at least `minImagesPerDay` files is checked, every other day folder is unchecked (see section 5).
6. **Preview** (section 6), then execute the checked steps, write the log, update the database.

- If a folder with that name already exists in `Input`, the files are moved into it.
- **Name conflict:** if the day folder already contains a file with the same name, the file is **not** renamed (no `_2`). It stays directly in `Input`, is shown in the preview as a conflict (unchecked, cannot be checked) and is logged as `REJECTED` with the reason. Files lying flat in `Input` cannot have the same name among themselves, so a conflict can only come from an existing folder.
- Unchecked files stay directly in `Input`.

## 5. Setting
- `settings.json`: `minImagesPerDay`, default `5`.
- Images and videos both count. The key keeps the name `minImagesPerDay` because the GUI label is „Mindestanzahl Bilder pro Tag“.
- Meaning: a day with **at least** this many files gets its folder checked by default (5 files = checked, 4 files = unchecked) (confirmed).

## 6. Preview
Based on the base preview (Git-style, left before, right after, checkboxes, collapsible folders), with these additions:

- **Tree:** the right side shows the day folders as a tree. Each folder row shows the number of files, e.g. `2024-07-13 (12 Dateien)`. Below it are the files that would be moved there.
- **Folder checkbox:** checks or unchecks the whole day. Single files inside can still be unchecked.
- **Source of the date:** each file row shows where its date comes from, e.g. `IMG_0412.jpg  (EXIF)`, `IMG-20240713-WA0001.jpg  (Dateiname)`, `scan.png  (Dateidatum)`. Files with the weak source "Dateidatum" are shown in grey italics, so uncertain dates are easy to spot.
- **Threshold control** at the top of the dialog (GUI labels):
  - Label „Mindestanzahl Bilder pro Tag“
  - Number field, prefilled with `minImagesPerDay` from `settings.json`
  - Button „Übernehmen“
- **Übernehmen** recalculates the checkboxes with the new value: at least that many files = checked, fewer = unchecked. Manual choices have priority (confirmed):
  - A day folder you checked or unchecked by hand keeps your choice. „Übernehmen“ only changes folders you have not touched.
  - Folders set by hand are marked with a small hand symbol, so you can see which ones the threshold no longer changes.
  - Right-click on such a folder offers „Automatisch setzen“ (confirmed). It removes the hand mark, and the folder follows the threshold again.
- The changed value only applies to this preview. `settings.json` is not changed.
- Summary at the bottom as in the base, plus: number of day folders checked / unchecked.

## 7. Log and undo
- File name: `YYYY-MM-DD_HH-MM-SS - Images - GroupByCaptureDate.log`.
- Step types as in the base: `FOLDER_CREATED`, `MOVED`, `REJECTED`.
- Additionally per moved file the capture date and its source, so it can be checked later why a file went to that day.
- Undo as in the base: files go back directly into `Input`, the day folders created by this action are removed if they become empty.

## 8. Notes on the base (not entered there)
- **Function-specific preview control:** the threshold field with „Übernehmen“ extends the base preview. Base section 5 has no such controls.
- **Additional info per row** (number of files, source of the date) in the preview.
- **New settings** `minImagesPerDay`, `imageExtensions` and `videoExtensions` in `settings.json`.
- Uses `CaptureDate` and `CaptureDateSource` (new columns, see `2.1 - InitializeFolder.md`).
- **Exception to the base name-conflict rule:** base section 2 appends `_2`, `_3`. This function never renames, a conflicting file stays in `Input` instead.
