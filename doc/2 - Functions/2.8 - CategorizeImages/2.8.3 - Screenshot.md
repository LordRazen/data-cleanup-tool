# 2.8.3 Category: Screenshot (v0.2)

- Internal name: `Screenshot`
- GUI label: **Screenshots**
- Folder: `Input/Screenshots` (pre-sorted by 2.8), later `Result/Screenshots` (moved by 2.9, `target` `Result`, kept, confirmed), one subfolder per year (confirmed)
- Definition file: `System/Config/Categories/Screenshot.json`
- Part of `2.8 - CategorizeImages.md`. Common rules (procedure, preview, log, undo, Default, pre-assessment) are defined there.
- Language: this document and the definition file are in English. Only GUI-visible values are in German.

## 1. What belongs here
- Every screenshot of a phone, tablet or computer screen that no more specific category fits: chats, websites, apps, maps, tickets, settings, error messages, game scenes, social media posts without a joke.
- Typical signs: status bar with time and battery, app or browser frame, buttons, menus, keyboard.

## 2. What does not belong here
- **More specific categories win** (proposal): a screenshot of a recipe is a Recipe (2.8.1), a screenshot of a meme or joke is a Meme (2.8.2). This is stated in the definition, so Claude picks the specific category.
- Photos of a screen taken with a camera (with reflections, at an angle): Default, unless another category fits.

## 3. Keyword
- A short German description of the content, 2 to 5 words, e.g. `Chat mit Anna Geburtstag`, `Bahnticket Berlin München`, `Fehlermeldung Windows Update`, `Google Maps Route Hotel`.
- Date first, then the keyword (confirmed): `YYYY-MM-DD - <keyword>`, e.g. `2023-05-14 - Bahnticket Berlin München.png`. The date is the capture date from the database (`CaptureDate`, see 2.1).
- One subfolder per year of the capture date (confirmed): `Screenshots/2023/2023-05-14 - Bahnticket Berlin München.png`.

## 4. Definition file (sent to Claude word for word)
```json
{
  "name": "Screenshot",
  "label": "Screenshots",
  "folder": "Screenshots",
  "target": "Result",
  "keywordPrefix": "CaptureDate",
  "subfolderByYear": true,
  "namePatterns": ["screenshot", "bildschirmfoto", "screen shot", "bildschirmaufnahme", "capture", "snip", "snipping", "ausschneiden", "scr_"],
  "definition": "The image is a screenshot of a phone, tablet or computer screen, e.g. a chat, a website, an app, a map, a ticket, settings or an error message. Typical signs: status bar with time and battery, app or browser frame, buttons, menus, on-screen keyboard. If the screenshot shows a recipe or a meme/joke, choose that more specific category instead. A camera photo of a screen is NOT a screenshot.",
  "keywordRule": "A short German description of the content in 2 to 5 words, e.g. 'Chat mit Anna Geburtstag', 'Bahnticket Berlin München', 'Fehlermeldung Windows Update'. No personal data such as phone numbers, addresses or passwords in the keyword."
}
```
- `keywordPrefix` (new optional key, see 2.8 section 3): `CaptureDate` puts `YYYY-MM-DD - ` in front of the keyword. Without it, the name is the keyword alone.

## 5. Pre-assessment by file name
- Screenshot names are very typical: `Screenshot_20230514-101112.png` (Android), `Bildschirmfoto 2023-05-14 um 10.11.12.png` (Mac), `Screenshot 2023-05-14 101112.png` (Windows). `namePatterns` in section 4.
- Additional local hint (proposal): image size equals a common screen resolution (e.g. 1080×2400, 1170×2532, 1920×1080) and the file has no camera EXIF data (no camera model). Shown as „Bildgröße passt zu einem Bildschirm“.

## 6. Privacy
- Screenshots often contain private content (chats, tickets, bank apps). They may still be sent to Claude (confirmed). Like every image in 2.8 the smaller copy and the file name are sent through the Claude subscription.
- The keyword must not contain personal data (rule in the definition).
