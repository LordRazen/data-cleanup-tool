# 2.9 Function: MoveCategoryFolders (v0.1)

- Internal name: `MoveCategoryFolders`
- Script: `System/Code/Images/MoveCategoryFolders.ps1`
- Group: Bilder (`Images`)
- Called by its own button: **Kategorien verschieben** (GUI label, proposal), see `2 - FunctionOverview.md`
- Tooltip (GUI): „Verschiebt die vorsortierten Kategorieordner aus Input an ihr Ziel: Rezepte, Screenshots und Sonstiges nach Result, Memes nach ToDelete“
- Second step after `2.8 - CategorizeImages.md` (Razen, 2026-10-30: first pre-sort in Input, then move over in a separate step).
- Extends the base specification v0.20 (`1 - Base.md`). The base stays unchanged. Where this function would need a change to the base, it is listed in section 8.
- Language: this document and the code are in English. Only GUI-visible values are in German.

## 1. Purpose
- Moves the content of the category folders in `Input` (created by 2.8) to their target, keeping the subfolders:
  - `Input/Rezepte/Backen/Apfelkuchen.jpg` → `Result/Rezepte/Backen/Apfelkuchen.jpg`
  - `Input/Screenshots/2023/2023-05-14 - Bahnticket.png` → `Result/Screenshots/2023/2023-05-14 - Bahnticket.png`
  - `Input/Sonstiges/IMG_2232.png` → `Result/Sonstiges/IMG_2232.png`
  - `Input/Memes/IMG_2233.jpg` → `ToDelete/Memes/IMG_2233.jpg`
- Renames nothing (except `_2` on name conflicts).

## 2. Scope
- `InputAndResult` (proposal). Moves only from `Input` to `Result` or `ToDelete`. Never moves anything inside or out of `Result`.

## 3. Which folders
- Exactly the folders directly in `Input` whose name equals the `folder` of an enabled category definition (2.8 section 3), plus `Input/Sonstiges` (Default).
- Target per folder from the definition: `target` `Result` → `Result/<folder>`, `target` `ToDelete` → `ToDelete/<folder>`. Default → `Result/Sonstiges`.
- All other folders and files in `Input` are not touched.

## 4. Procedure
1. **Collect** all files in the category folders (with subfolders).
2. **Plan:** each file to the same relative path below the target folder. Missing target folders are created (`FOLDER_CREATED`).
   - Target folder already exists: contents are merged (as in 2.5).
   - Name conflict: base rule `_2`.
   - Same hash already in the target: duplicate, not moved, shown as a conflict, logged as `REJECTED` with the hint to run „Input initialisieren“ first (as in 2.5).
3. **Preview**, execute, log. The emptied category folders in `Input` are removed by the main program (base rule).

## 5. Preview
- Base preview (Git-style), grouped by category folder: „Rezepte → Result (12)“, „Memes → ToDelete (25)“ etc. `Input`, `Result` and `ToDelete` are shown.
- All rows checked. A whole group can be unchecked with one click (e.g. keep Sonstiges in Input for now).
- Warning before the preview if files have not been checked for duplicates yet (`DuplicateChecked` empty), same message as in 2.5.

## 6. Log and undo
- File name: `YYYY-MM-DD_HH-MM-SS - Images - MoveCategoryFolders.log`.
- Step types as in the base: `MOVED`, `FOLDER_CREATED`, `EMPTY_FOLDER_REMOVED`, `REJECTED`.
- Undo as in the base: files go back into the category folders in `Input`, folders created in `Result` or `ToDelete` by this action are removed if they become empty.

## 7. Relation to 2.5
- `MoveToResult` (2.5) moves by hand to one chosen target. This function moves all category folders at once to their fixed targets, without choosing. Both use the same helpers in `Common.ps1`.

## 8. Notes on the base (not entered there)
- **Moves to `ToDelete`** besides `Result`. Base section 7 knows only `Input` and `InputAndResult`; `ToDelete` is treated like `Result` for the scope.
- **Reads the category definitions** of 2.8 (`System/Config/Categories/`).
