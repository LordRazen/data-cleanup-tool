# 2.6 Function: DeterminePlaceByGps (v0.2)

- Internal name: `DeterminePlaceByGps`
- Script: `System/Code/Images/DeterminePlaceByGps.ps1`
- Group: Bilder (`Images`)
- Called by button: **Ort bestimmen (OpenStreetMap)** (GUI label, proposal), see `2 - FunctionOverview.md`
- Tooltip (GUI): „Bestimmt aus den GPS-Daten der Fotos den Ort jedes Tagesordners und ergänzt ihn im Ordnernamen“
- Uses endpoint `3.2 - NominatimEndpoint.md` (free). Sends only rounded coordinates, never images or file names.
- Extends the base specification v0.20 (`1 - Base.md`). The base stays unchanged. Where this function would need a change to the base, it is listed in section 8.
- Language: this document and the code are in English. Only GUI-visible values are in German.

## 1. Purpose
- Determines the place of each day folder from the GPS data of its photos and videos, and adds it to the folder name: `2024-07-13` → `2024-07-13 - Tokio` (format `YYYY-MM-DD - <Place>`).
- Free first (confirmed): this function only uses OpenStreetMap. Folders without GPS data stay unchanged and can then be handled by `2.7 - DeterminePlaceByClaude.md`.
- Renames only folders, never files.

## 2. Scope
- `Input` only (confirmed). Works on the day folders created by `GroupByCaptureDate` directly in `Input`.

## 3. Which folders
- Folders directly in `Input` whose name is exactly `YYYY-MM-DD`, i.e. without a place yet.
- Folders that already have a place (`YYYY-MM-DD - …`) are skipped (confirmed).
- Other folders are ignored, with the same warning list as in `2.3 - GroupByCaptureDate.md`.

## 4. Procedure
1. **GPS per file:** latitude and longitude come from the database (`Latitude`, `Longitude`, read from EXIF by `InitializeFolder`, see section 8). Files without GPS are left out.
2. **Group coordinates:** coordinates are rounded as in 3.2 (3 decimals, about 100 m). Each distinct rounded coordinate is looked up only once (and the cache of 3.2 avoids asking twice across runs).
3. **Limit per folder:** at most `maxLookupsPerFolder` distinct coordinates per folder (default 10), spread evenly over the day, so a folder with 500 photos does not cause 500 requests.
4. **Place per folder:** the place (city, town or village) that most files of the folder belong to.
   - If a second place has at least `secondPlaceShare` of the files (default 30 %), both are named (confirmed): `2024-07-13 - Tokio, Kyoto`. The share is adjustable in the settings.
   - If no file of the folder has GPS: folder stays unchanged, shown as „kein GPS“ in the preview.
5. **Plan:** rename the folder (base: renaming = moving under a new name).
6. **Preview**, execute, log.

## 5. Preview
- Base preview (Git-style): left the old folder name (red), right the new name (green), with the files inside unchanged.
- Each folder row shows how sure the result is, e.g. „Tokio (42 von 45 Dateien mit GPS)“.
- „© OpenStreetMap-Mitwirkende“ is shown in the preview, as the policy of 3.2 requires.
- The new name can be edited directly in the preview before „Ausführen“ (confirmed), e.g. `Tokio` → `Tokio Shibuya`. Only the part after `YYYY-MM-DD - ` is editable. Characters not allowed in Windows folder names (`\ / : * ? " < > |`) are refused with a short note.
- Folders without GPS appear as an info line „kein GPS – wird übersprungen“, without a checkbox.
- Name conflict: if a folder with the new name already exists, base rule `_2`.

## 6. Errors
- Nominatim offline or blocked (see 3.2): the function keeps all places found so far, the remaining folders stay unchanged and are shown as „Ort konnte nicht bestimmt werden“.

## 7. Log and undo
- File name: `YYYY-MM-DD_HH-MM-SS - Images - DeterminePlaceByGps.log`.
- Folder renames as `MOVED` (old name, new name), plus `API_CALL` lines for the lookups.
- Undo as in the base: the folder gets its old name back. Database paths of the files inside follow (base rule).

## 8. Notes on the base (not entered there)
- **New columns `Latitude` and `Longitude`** in table `Files`, filled by `InitializeFolder` from EXIF (GPS tags 0x0002 and 0x0004 with their N/S and E/W references). Added to `2.1 - InitializeFolder.md`.
- **Editable name in the preview** (confirmed): base section 5 has no editable fields.
- **New settings** `maxLookupsPerFolder` and `secondPlaceShare` in `settings.json` (section `places`).
