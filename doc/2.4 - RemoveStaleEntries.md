# 2.4 Function: RemoveStaleEntries (v0.2)

- Internal name: `RemoveStaleEntries`
- Script: `System/Code/Database/RemoveStaleEntries.ps1`
- Called by fixed button: **Datenbank bereinigen** (GUI label, proposal), bottom of the main window next to the other fixed buttons, not part of any group (confirmed), see `2 - FunctionOverview.md`
- Tooltip (GUI): „Entfernt Datenbankeinträge zu Dateien, die es nicht mehr gibt“
- Extends the base specification v0.20 (`1 - Base.md`). The base stays unchanged. Where this function would need a change to the base, it is listed in section 7.
- Language: this document and the code are in English. Only GUI-visible values are in German.

## 1. Purpose
- Cleans up the database: removes every entry in table `Files` whose file no longer exists at its stored `Path` (confirmed).
- Only database rows are removed. Never a file.
- Fast: only checks whether the file exists. No hashes are computed.

## 2. Relation to InitializeFolder
- `InitializeFolder` already removes missing entries, but only for the folder it initializes (`Input` or `Result`, base section 10) and only after hashing the whole folder.
- `RemoveStaleEntries` does the same cleanup on its own, for all folders at once, without hashing. It also covers `Doublets`, which no initialization touches.
- Proposal: `InitializeFolder` keeps its own cleanup step as confirmed in the base. Both use the same shared helper in `Common.ps1`, so the rule is defined once.
- Note: `InitializeFolder` can detect a file that was moved by hand (same hash, new path) and keeps its entry. `RemoveStaleEntries` cannot, it simply removes the old entry. The file gets a new entry at its new place with the next initialization. Nothing is lost except the stored hash, which is recomputed.

## 3. Scope
- All entries in the database (confirmed), i.e. paths under `Input/`, `Result/` and `Doublets/`.
- Reads only whether files exist. Changes no files.

## 4. Procedure
1. **Check:** for every entry, test whether the file exists at `Path`.
2. **Safety check:** if a whole main folder (`Input`, `Result`, `Doublets`) is missing, or more than half of its entries are missing, the function warns and does not offer those entries pre-checked (GUI message: „Der Ordner Result fehlt oder ist größtenteils leer. Ist die Platte richtig angeschlossen?“). This protects the database if the drive or a folder is temporarily not reachable.
3. **Preview:** list of the entries to be removed (section 5).
4. **Execute:** remove the checked entries, write the log.

## 5. Preview
- No files move, so instead of the Git-style comparison a simple list grouped by main folder (`Input`, `Result`, `Doublets`), one line per entry with path, size and capture date.
- One checkbox per entry and per main folder, all checked by default (except in the safety case of section 4).
- Buttons as in the base: „Alle annehmen“, „Alle ablehnen“, „Ausführen“, „Abbrechen“.
- Summary: entries checked, entries found in total, entries to be removed.
- If nothing is stale: only the message „Keine veralteten Einträge gefunden.“, no preview.

## 6. Log and undo
- File name: `YYYY-MM-DD_HH-MM-SS - Database - RemoveStaleEntries.log`.
- New step type `ENTRY_REMOVED` with the full row (path, hashes, size, dates), so nothing is lost.
- Undo (confirmed): restores the removed rows from the log, but only for paths that do not have an entry again in the meantime.

## 7. Notes on the base (not entered there)
- **New fixed button** „Datenbank bereinigen“ next to „Result initialisieren“, „Input initialisieren“ and „Aktion rückgängig machen“. Base section 5 lists only three fixed buttons.
- **Preview as a list** instead of the Git-style comparison for a function that only changes the database.
- **New step type** `ENTRY_REMOVED`, and undo of database-only changes (base section 9 only undoes file moves).
