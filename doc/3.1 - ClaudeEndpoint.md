# 3.1 Endpoint: ClaudeEndpoint (v0.3)

- Internal name: `ClaudeEndpoint`
- Script: `System/Code/Api/ClaudeEndpoint.ps1`
- Part of `3 - API.md`. Language: document and code in English, only GUI-visible values in German.

## 1. Purpose
- Lets functions ask Claude something, e.g. "What does this image show?" or "Which event name fits these photos?", and get a structured answer back.
- Uses the Claude subscription (Pro) that is already paid. **Never pay per use** (confirmed).

## 2. Why Claude Code and not the API
- The Claude Pro plan (about 20 USD per month) does **not** include access to the Anthropic API. The API is a separate product billed per use with its own key. That is excluded (confirmed).
- The Pro plan does include **Claude Code**. Claude Code can be called headless from the command line, and it then runs on the subscription (confirmed as option 1).

## 3. How a call works
- The endpoint starts the local Claude Code in headless mode:
  `claude -p "<prompt>" --output-format json`
- The answer is a JSON object. The endpoint reads `result` (the answer text) and `is_error`. If the function asked for JSON, the endpoint parses `result` as JSON and checks it.
- **No tools:** Claude may not run commands or change files. The call allows no tools except reading the file or files that are passed (e.g. an image), so Claude can look at it.
- **Working folder:** the call runs in `System/Temp/Claude/`, an empty folder, so Claude does not see or load anything else from the disk.
- **Guarantee for the subscription:** if the environment variable `ANTHROPIC_API_KEY` is set, Claude Code would use that key and bill per use. The endpoint therefore always starts Claude Code with this variable removed for the started process. This way the call can only run on the subscription.
- One call at a time. No parallel calls.

## 4. Requirements and availability check
`Test-ClaudeEndpoint` checks, before a function starts:
1. **Installed:** `claude` (or the path from the settings) can be found. If not: `NotInstalled`.
2. **Logged in:** a tiny test call succeeds. If Claude Code answers that no one is logged in: `NotLoggedIn`.
3. **Enabled:** `api.claude.enabled` is `true`.

If the check fails:
- Buttons of functions that need Claude are greyed out. Their tooltip says why (GUI), e.g. „Claude ist nicht installiert. Installiere Claude Code und melde dich einmal mit deinem Konto an.“ or „Claude ist nicht angemeldet. Starte einmal ‚claude‘ in der Eingabeaufforderung und melde dich an.“
- Everything else in the tool keeps working.

## 5. Usage limits
- The Pro plan has usage limits that reset after a few hours. When the limit is reached, Claude Code answers with an error instead of a result.
- The endpoint detects this and returns `LimitReached`, with the reset time if Claude Code gives one.
- The run then **waits** until the limit is reset and continues automatically (confirmed). During the wait a dialog is shown (GUI):
  - Text: „Das Claude-Nutzungslimit ist erreicht. Es geht automatisch weiter um <Uhrzeit>.“ with a countdown, and the progress so far, e.g. „120 von 300 Dateien bearbeitet“.
  - Button „Rest überspringen“: stops the waiting, skips all files not yet processed and keeps all results so far (confirmed). The function then continues with its preview as usual, based on these results.
  - If Claude Code gives no reset time, the endpoint checks again with a tiny test call every `limitRetryMinutes` minutes. The dialog then says „Nächster Versuch um <Uhrzeit>.“
- Skipped files are logged as `API_CALL` with result `Skipped`.
- No fast retries in a loop: while waiting, only the scheduled checks run, so the limit is not wasted.
- `maxCallsPerRun` limits the number of calls per function run, so one run cannot use up the whole limit by accident.

## 6. Settings (`settings.json`, section `api.claude`)

| Key | Default | Meaning |
|---|---|---|
| `enabled` | `true` | switch the endpoint on or off |
| `executable` | `claude` | command or full path of Claude Code |
| `model` | empty | empty = default of Claude Code (confirmed); a model name can be set later if needed |
| `timeoutSeconds` | `120` | a call that takes longer is cancelled (`Timeout`) |
| `maxCallsPerRun` | `100` | maximum calls per function run |
| `workingFolder` | `System/Temp/Claude` | empty folder the call runs in |
| `limitRetryMinutes` | `15` | how often to check again while waiting for the limit, if no reset time is known |

## 7. Interface for functions
```powershell
$answer = Invoke-ClaudeEndpoint -Prompt "Describe the place shown in this photo." `
                                -File "Input/IMG_0412.jpg" `
                                -ExpectJson
if ($answer.Success) { $answer.Data } else { $answer.ErrorKind }
```
- `-Prompt`: the question in English.
- `-File` (optional): one file Claude may read, relative to `SortingTool`.
- `-Files` (optional): several files Claude may read in one call, e.g. sample images of a folder. Claude may read only these files.
- `-ExpectJson` (optional): Claude is asked to answer only with JSON, the endpoint checks it and returns `InvalidResponse` otherwise.

## 8. Privacy
- The prompt and the passed file are sent to Anthropic as part of the subscription. Each function that uses this endpoint states in its specification which files it sends.
