# 2.7 Function: DeterminePlaceByClaude (v0.2)

- Internal name: `DeterminePlaceByClaude`
- Script: `System/Code/Images/DeterminePlaceByClaude.ps1`
- Group: Bilder (`Images`)
- Called by its own button: **Ort bestimmen (Claude)** (GUI label), separate from 2.6 (confirmed), see `2 - FunctionOverview.md`
- Tooltip (GUI): „Lässt Claude anhand einiger Fotos den Ort von Tagesordnern ohne Ort schätzen“
- Uses endpoint `3.1 - ClaudeEndpoint.md` (Claude subscription, never pay per use).
- Extends the base specification v0.20 (`1 - Base.md`). The base stays unchanged. Where this function would need a change to the base, it is listed in section 8.
- Language: this document and the code are in English. Only GUI-visible values are in German.

## 1. Purpose
- Estimates the place of day folders that have no place yet, from the content of a few photos (landmarks, signs, landscape), and adds it to the folder name: `2024-07-13` → `2024-07-13 - Tokio`.
- Meant as the second step after `2.6 - DeterminePlaceByGps.md` (free first, confirmed).
- Renames only folders, never files.

## 2. Scope
- `Input` only (confirmed).

## 3. Which folders
- Only folders directly in `Input` named exactly `YYYY-MM-DD`.
- **Folders that already have a place in their name** (`YYYY-MM-DD - …`), e.g. from 2.6 or set by hand, are skipped (confirmed). So no Claude call is wasted on them.
- If Claude is not available (see 3.1), the button is greyed out with the reason as tooltip.

## 4. Procedure
1. **Choose sample images by hand** (confirmed, no automatic choice). A selection dialog opens first:
   - Left: the list of folders without a place.
   - Right: thumbnails of the images of the selected folder, each with a checkbox. Nothing is checked at the start.
   - You check the images Claude should look at, e.g. the ones with a landmark or a sign. At most `maxImagesPerFolder` per folder (default 5) as protection for the usage limit, the dialog says when the maximum is reached.
   - Folders where no image is checked are skipped, no Claude call.
   - Only images can be chosen, no videos.
   - Buttons: „Weiter“ (asks Claude for all folders with chosen images) and „Abbrechen“.
2. **Ask Claude:** one call per folder with these images and the date. Prompt (English):
   "These photos were taken on <date>. Where were they most likely taken? Answer only with JSON: {\"place\": city or town in German, \"country\": country in German, \"confidence\": number from 0 to 1, \"reason\": short reason in German}. If you cannot tell, set place to null."
3. **Check the answer:** `place` empty or `confidence` below `minConfidence` (default 0.6) → the folder is proposed, but unchecked.
4. **Plan:** rename the folder to `YYYY-MM-DD - <place>`.
5. **Preview**, execute, log.
- Usage limit reached: as in 3.1 (wait, or „Rest überspringen“ and keep the results).

## 5. Preview
- Same as 2.6 (Git-style rename, name editable directly in the preview, confirmed).
- Each folder row shows Claude's confidence and reason, e.g. „Tokio – 85 % – Tokyo Tower im Hintergrund“.
- Folders below `minConfidence` are unchecked and shown in grey italics. A place guessed by Claude is never applied without your look in the preview.
- Name conflict: base rule `_2`.

## 6. Privacy
- Only the images you chose (up to 5 per folder) and the date are sent to Anthropic through the Claude subscription. Nothing else, no file names, no GPS.

## 7. Log and undo
- File name: `YYYY-MM-DD_HH-MM-SS - Images - DeterminePlaceByClaude.log`.
- Folder renames as `MOVED`, plus `API_CALL` lines with place, confidence and reason.
- Undo as in the base.

## 8. Notes on the base (not entered there)
- **Several files per Claude call:** the interface of `3.1 - ClaudeEndpoint.md` gets `-Files` (a list) in addition to `-File`. Added to 3.1.
- **Selection dialog with thumbnails** before the Claude calls.
- **New settings** `maxImagesPerFolder` and `minConfidence` in `settings.json` (section `places`).
