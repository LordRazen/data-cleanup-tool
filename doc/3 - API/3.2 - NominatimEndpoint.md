# 3.2 Endpoint: NominatimEndpoint (v0.2)

- Internal name: `NominatimEndpoint`
- Script: `System/Code/Api/NominatimEndpoint.ps1`
- Part of `3 - API.md`. Language: document and code in English, only GUI-visible values in German.
- Service: OpenStreetMap Nominatim, public server `https://nominatim.openstreetmap.org`
- Usage policy (checked 2026-10-28): https://operations.osmfoundation.org/policies/nominatim/

## 1. Purpose
- Turns GPS coordinates into a place name ("reverse geocoding"), e.g. `35.6764, 139.6500` → `Tokio, Japan`.
- First choice for place lookups, because it is free and needs no account or key. Claude is only used later, when there are no coordinates (see `3 - API.md`).
- Used later by a function that determines the place of a folder from the GPS data of its photos (planned as 2.6).

## 2. Why Nominatim
- Free, no key, no account, no billing at all. Fits the rule "never pay per use".
- Google Maps Geocoding is billed per use and needs a key and a payment method, so it is excluded.
- The data comes from OpenStreetMap and is good worldwide down to city and district level.

## 3. Rules of the usage policy and how the endpoint follows them

| Rule of the policy | How the endpoint follows it |
|---|---|
| At most 1 request per second | The endpoint waits at least 1.1 seconds between two requests. One request at a time, never in parallel. |
| Scripts running regularly or longer than a day: at most 4 per minute | The tool only runs when you click a button, never on a schedule. Still, `maxRequestsPerRun` limits one run. |
| Identify the application with a valid User-Agent, no default library User-Agent | Fixed User-Agent `SortingTool/<version> (private photo sorting tool)`, no contact e-mail (confirmed). |
| Results must be cached on the client side, the same query must not be repeated | Every answer is stored in the database (section 5). The same place is asked only once, ever. |
| No systematic queries (e.g. grid scans) | Only real coordinates from real photos are asked, and the calling function sends one request per group of photos, not per photo. |
| Bulk use only single-threaded on one machine | One thread, one computer. |
| Show attribution | Wherever a place name from Nominatim appears in the GUI, „© OpenStreetMap-Mitwirkende“ is shown next to it. The log notes the source too. |
| The service must be switchable off without a software update | Setting `api.nominatim.enabled`. |
| Do not send personal data | Coordinates are rounded before sending (section 4), only coordinates are sent, never file names or images. |
| The policy can change at any time | The endpoint reacts to blocks (HTTP 403/429) by stopping (section 6). |

## 4. How a call works
- Request:
  `GET https://nominatim.openstreetmap.org/reverse?format=jsonv2&lat=<lat>&lon=<lon>&zoom=<zoom>&addressdetails=1&accept-language=<language>`
- **Rounding:** latitude and longitude are rounded to `coordinatePrecision` decimal places before sending (default 3, about 100 m). This is precise enough for a city or district, makes cache hits much more likely and does not send the exact position of, for example, your home.
- **Zoom:** `zoom` sets the level of detail of the answer. Default `10` = city. `14` would be the district.
- **Language:** place names in German (`accept-language=de`), because they are shown in the GUI and later used in folder names.
- **Answer:** the endpoint reads from `address`: `city` (or `town`, `village`, `municipality` if there is no city), `suburb`, `county`, `state`, `country`, `country_code`, plus `display_name`.
- Returns `Data` with these fields plus `Place`, the short name for folder names: the city (or town or village).

## 5. Cache
- New table `GeoCache` in the database:

| Column | Content |
|---|---|
| `Latitude` | rounded latitude |
| `Longitude` | rounded longitude |
| `Zoom` | zoom used |
| `Language` | language used |
| `Response` | the answer as JSON |
| `Place` | short place name |
| `RetrievedAt` | time of the request |

- Before every request the endpoint looks in the cache first. On a hit no request is sent.
- Cache entries never expire. Places hardly change.

## 6. Errors
- The tool is always used online (confirmed). There is no offline fallback.
- **No internet:** `ErrorKind` = `Offline`. The calling function skips the place lookup and shows (GUI): „Keine Internetverbindung. Der Ort kann gerade nicht bestimmt werden.“
- **HTTP 429 (too many requests) or 403 (blocked):** `LimitReached`. The endpoint stops all further requests in this run, does not retry and shows (GUI): „OpenStreetMap hat die Anfragen vorübergehend gesperrt. Bitte später erneut versuchen.“ This protects against being blocked permanently.
- **No place found** (e.g. a photo taken at sea): `Success` with `Place` empty.
- **Timeout:** after `timeoutSeconds`, `Timeout`.

## 7. Settings (`settings.json`, section `api.nominatim`)

| Key | Default | Meaning |
|---|---|---|
| `enabled` | `true` | switch the endpoint on or off |
| `baseUrl` | `https://nominatim.openstreetmap.org` | server address, could later point to a different or own Nominatim server |
| `zoom` | `10` | level of detail, 10 = city |
| `language` | `de` | language of the place names |
| `coordinatePrecision` | `3` | decimal places sent, 3 ≈ 100 m |
| `minSecondsBetweenRequests` | `1.1` | minimum pause between requests, may not be set below 1 |
| `maxRequestsPerRun` | `200` | maximum requests per function run |
| `timeoutSeconds` | `20` | maximum time per request |

## 8. Interface for functions
```powershell
$answer = Invoke-NominatimEndpoint -Latitude 35.676423 -Longitude 139.650027
if ($answer.Success) { $answer.Data.Place }   # "Tokio"
```
